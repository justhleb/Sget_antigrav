## 1. ОБЩЕЕ ОПИСАНИЕ СИСТЕМЫ

Разработанная система представляет собой дискретно-событийную имитационную модель для анализа работы и экономической оптимизации трамвайной сети. Модель построена на базе библиотеки SimPy и поддерживает одновременную симуляцию нескольких маршрутов в прямом и обратном направлениях в рамках **единого общего парка трамваев**.

В последних версиях система осуществляет переход от микро-симуляции очередей пассажиров к **макро-экономической оценке эффективности**, основываясь на расчётах реальной статистики доходов.

### Основные задачи модели:

- Обработка исторических данных из многоуровневых Excel-отчётов о доходах (revenue) и пассажиропотоке
- Моделирование движения трамваев с отслеживанием интервалов и отклонений от целевых графиков
- Расчёт планового дохода и расчетного пассажиропотока на рейс на основе реальных удельных показателей (руб/км, пасс/км)
- Подсчёт транспортных показателей: трамвай-километры и суммарный доход
- Визуализация финансовых показателей работы (Financial Summary) и анализ узких мест
- Оптимизация размера парка и распределения трамваев методом **NSGA-II** для максимизации совокупного дохода системы при минимизации отклонений от графика

Модель позволяет тестировать различные конфигурации расписания и размера парка без проведения дорогостоящих натурных экспериментов. Является основой для экономической и операционной оптимизации.

## 3. ЛОГИКА РАБОТЫ МОДЕЛИ И ЭКОНОМИКА

### 3.1 Инициализация системы

При запуске мультимаршрутной симуляции происходит:

1. Загрузка конфигурационных JSON-файлов для каждого маршрута (fwd + bwd)
2. Загрузка **экономических нормативов** (доход на км, пассажиры на км) из директории `data_sensors` (Excel-парсер)
3. Инъекция макро-экономических показателей напрямую в конфигурации маршрутов
4. Создание `TramPair` (связки прямого и обратного направлений маршрута), выделение трамваев
5. Параллельный запуск всех маршрутов в среде SimPy

### 3.2 Архитектура TramPair

Каждая пара fwd/bwd работает через три SimPy Store:
`pool (депо)` → `[fwd прогон]` → `fwd_done` → `[разворот]` → `[bwd прогон]` → `bwd_done` → `[отдых]` → `pool`

### 3.3 Диспетчеризация по расписанию

Трамваи выпускаются по расписанию из JSON-конфига (`schedule`). Каждый рейс (`TripSchedule`) содержит плановые времена. **Ключевое правило:** если в момент планового отправления в пуле нет свободного трамвая — рейс **пропускается** с записью в лог. Это исключает снежный ком задержек.

### 3.4 Макро-Экономическая Модель Доходов и Пассажиропотока

Симуляция перешла от микро-уровня (расчёт посадок-высадок пуассоновским процессом для каждой остановки) к **Top-Down (сверху-вниз)** экономическому подходу:

1. **Доход за рейс** привязан к реализованному в рейсе физическому пробегу (в километрах). Исключена ситуация, при которой модель получает выгоду за счет задержек в рейсе. `trip_revenue = run_km * (average_revenue_per_km_from_excel)`.
2. **Пассажиропоток** также оценивается макро-методом на основании агрегированных исторических данных `trip_pax_estimated = run_km * (average_passengers_per_km_from_excel)`.
3. Модуль `excel_parser.py` автоматически считывает `summary_reports_*.xlsx` для получения средних метрик эффективности конкретного подвижного состава и формирует нормативы перед стартом.

### 3.5 Логика остановки

На остановке:

- **Время стоянки** зафиксировано (константа 1.0 мин), т.к. пассажиры рассчитываются на рейс в целом.
- Производится расчёт ошибки выполнения интервала (`actual_headway` vs `target_headway`).
- Осуществляется логирование для анализа отклонений.

## 3.6 Расчёт времени движения

Время проезда между остановками зависит от медианного времени хода, `flow_speed` и параметра почасвой загруженности дорог (`road_loads`). В часы пик скорость может падать до ~10% от номинальной.

## 4. МОДУЛИ И ИХ ФУНКЦИИ

### 4.1 data_sensors/excel_parser.py

Парсер агрегированной финансовой статистики из Excel файлов (сущности `RouteEconomics` и `VehicleEconomics`). Отвечает за вычисление средних коэффициентов доходности и пассажиро-эффективности для каждого маршрута.

### 4.2 models/tram.py

Модель трамвая:

- Класс содержит `TramStats` (`total_trips`, `passengers_served`).
- Отслеживает события на перегонах и deviation log (`log_schedule_deviation`).

### 4.3 models/route.py

Ядро симуляции прогона.

- В конце маршрута `_tram_run` рассчитывает **макро-экономические метрики рейса** (выработка доходов и пассажиро-километраж) и обновляет глобальные суммы `RouteStats.total_revenue`.

### 4.4 simulation/multi_route.py

Оркестратор. Содержит функцию `get_objectives()`, которая возвращает 4 ключа профиля, включая:

- `total_tram_km`
- `headway_mae_min` (средняя ошибка интервального обеспечения)
- `total_revenue` (общая выручка)
- `total_passengers_est` (предсказание числа перевезенных лиц)

### 4.5 simulation/runner.py

CLI интерфейс: `python -m simulation.runner --routes 20 48 55 --trams 10 10 10`

### 4.6 visualization.py

Модуль построения аналитических графиков, сохраняет PNG-файлы. Поддерживает:

- **Отклонения**: `delay_by_stop.png`, `delay_by_hour.png`, `delay_heatmap.png` (генерируются для каждого маршрута отдельно).
- **Сводный Дашборд**: `global_financial_summary.png` (единый агрегированный финансовый дашборд для всей транспортной сети). Предоставляет сравнительный анализ рентабельности и пассажиропотока маршрутов вместо устаревшего моделирования микро-очередей.

### 4.7 logger.py

Логирование: создает `trams_summary.csv` и `schedule_deviations.csv`.

## 9. ОПТИМИЗАЦИЯ NSGA-II И ЭКОНОМИКА

Алгоритм оптимизации использует `pymoo` и ищет идеальный компромисс между экономикой контракта и качеством услуги.

**Переменные оптимизации** — количество выпускаемых трамваев на каждый маршрут:

- `n_20`, `n_48`, `n_55`. Диапазон от **0 до 12** шт.

**Целевые функции (2D-Парето):**

1. **`total_revenue`** (Максимизация) — выжимаем чистый доход
2. **`headway_mae`** (Минимизация) — обеспечиваем соблюдение плановых интервалов, снижаем среднюю абсолютную ошибку (в минутах)

**Ограничения:**

- Суммарный парк трамваев (`N_MAX`): контрактное ограничение в **30 единиц**.
- Индивидуальные максимумы (`MAX_PER_ROUTE`): **12 единиц**.

### Запуск и визуализация

```bash
python run_optimizer.py
```

После работы генерируются новые графики (`plot_pareto.py`):

1. **`pareto_revenue_vs_mae.png`** (Доход против Интервальной погрешности). Показывает классический Trade-Off: чем больше доход (набивка вагонов + пройденный путь), тем потенциально выше отклонения из-за недостатка резервов парка.
2. **`pareto_fleet_distribution.png` (Fleet Bar-Chart)** — Показывает распределение парка среди трех маршрутов для лучших экономических решений.
3. **`pareto_fleet_vs_revenue.png`** — Рассеяние: как общий размер парка коррелирует с итоговыми доходами.
